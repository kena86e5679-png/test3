# 空間偏好 AR：視野版

用手機後鏡頭看真實空間，套用「中央區清晰、外圍黑底白點」的視野規則，並依你的移動習慣在眼前生成白色線條的虛擬建築。

## 放到 GitHub Pages

（`server/` 資料夾是連線用的 Node.js 伺服器，不會在 GitHub Pages 上執行，見下面的 v6。）

1. 在 GitHub 建一個新的 repository（例如 `ar-vision`），設為 Public。
2. 把 `index.html`、`app.js`（以及這份 README）上傳到 repository 的根目錄。
3. Settings → Pages → Source 選 `Deploy from a branch`，Branch 選 `main`，資料夾選 `/ (root)`，按 Save。
4. 等 1～2 分鐘，網址會是 `https://你的帳號.github.io/ar-vision/`。
5. 用手機開這個網址（一定要 https，鏡頭和感測器才會開放）。

## 手機上的使用

- iPhone：用 Safari。按「開始」後，允許「動作與方向」和「相機」。
- Android：用 Chrome。允許相機即可。
- 手機直立拿著，邊走邊看。畫面左上角會顯示視野縮放、習慣比例與生成紀錄。
- 步伐由加速度計偵測，每一步前進「步長」公尺。偵測不到時，可以按住「按住前進」。
- 「校準前方」：把目前手機朝向設為前方。走一段路、方向漂掉時可以重按。
- 「視野限制」：開關視野規則，方便和原始畫面比較。
- 「設定」：中央區大小、相機視角、步長、點雲敏感度。

## 桌機測試

沒有方向感測器時，用滑鼠拖曳轉向，按住 W 前進。

## v2：空間偵測、附著生成、方位、懸疑場景

### 空間偵測管線（單眼、啟發式，每 4 格執行一次）
| 項目 | 做法 |
| --- | --- |
| 特徵點 | Harris 角點（畫面上的白色十字） |
| 線條偵測 | 以重力方向為前提：鉛直線上的像素有相同的「方位角」，對邊緣像素做方位角投票找出垂直線（青色線） |
| 地板、距離 | 垂直線的底端落在地面，用眼高 1.5 m + 手機俯仰角算出距離（標在底端的 m 數） |
| 柱 | 兩條接近的垂直線，底端距離相近、間距換算成寬度 0.1–0.9 m |
| 轉角 | 垂直線底端左右兩側的「地牆交線」方向不同（或有強角點），並沿交線追出牆段 |
| 語義分割（近似） | 地板：畫面下緣顏色（2-means，容許兩種地磚）＋區域生長，並用世界模型的牆剔除被牆擋住的區域；天花板：朝上且低紋理；其餘為牆。色塊：綠＝地板、橘＝牆、藍＝天花板 |
| 世界模型 | 公尺座標的實體（柱、轉角、牆邊）與牆段，跨影格融合、累積信心、看不到時衰減；可走地面記成 0.5 m 格子（「空間背景化」） |
| 深度／LiDAR | 只做能力檢查並顯示在資訊文字最後一行。iOS Safari 沒有深度介面；Android WebXR 深度需另開 session，不能與這條相機管線並用，所以距離一律用單眼估計 |

世界模型在 AR 畫面中以**青色**線條呈現（牆的上下緣與立柱、柱的方框、轉角的 L 形），虛擬建築是**白色**線條。「偵測層」按鈕可開關色塊、特徵點與垂直線；「重新掃描空間」清空世界模型。

### 附著式生成
虛擬建築不再隨機落地，而是從世界模型長出來（長出動畫約 2.6 秒，沿長度與高度生長）：
- 小房間：以偵測到的轉角為一角，補上兩面牆（一面留門）
- 巷弄：與真牆平行、偏移 1.9 m、同長度的牆
- 長牆：從真牆端點或既有虛擬牆端點沿方向延伸，或折 90°
- 掩體群：偵測到柱子時，柱子往上長一層並在周圍長出矮掩體；沒有柱子就貼著牆長

類型仍依你的移動習慣（空曠／貼牆／快走／停留）選擇。沒有偵測到任何牆柱角時不會生成，資訊文字會提示「掃描空間中」，請慢慢環視牆角與地面。桌機無鏡頭測試可在設定裡打開「自由生成」。

### 右上角方位
- 圓環：目前朝向的磁北方位（N 為紅色），外圈青點為世界模型實體、白點為虛擬建築的方位；內圈是俯仰／滾轉的人工地平線
- 數值：方位角與八方位、俯仰、滾轉、陀螺儀角速度
- 融合：方向感測器（陀螺儀融合）提供平滑的短時間方向，磁北量測（iOS `webkitCompassHeading`、Android `deviceorientationabsolute`）用互補濾波校正長期偏移。沒有羅盤時顯示「相對（無羅盤）」，此時 000° 只是你校準時的朝向
- 室內磁場干擾大，方位可能偏差數十度，請當作粗略參考

### AR 懸疑場景
「隨機移動」＝轉向忽左忽右（方向反轉次數）、轉向速度大、速度忽快忽慢。亂度（資訊文字最後一項）過高會觸發事件，事件間隔約 10–17 秒；安靜太久且在走動時也會偶爾觸發。設定裡的「觸發懸疑」可手動測試。
1. 周邊人影：只出現在視野邊緣（優先躲在柱子或轉角後），一看向中央就消失，再出現時更近（最多 3 次）
2. 牆上多一扇門：長在偵測到的牆上，門縫漏光；走近會關上
3. 視野閃爍：中央區忽然收縮、閃爍
4. 腳步聲：立體聲腳步由遠而近＋震動
5. 訊號故障：畫面切片錯位、世界模型短暫失真
6. 邊緣低語：只寫在黑色周邊區的短句

事件有聲音與震動（需要手機未靜音；iOS 不支援震動）。沒有任何攻擊或傷害判定，威脅物仍然關閉。

## v3：雙點對位（AR 座標 ↔ 基地座標）

把「手機姿態驅動基地模型」的概念先在網頁裡驗證。內建一個示範基地（房間、隔間、假門、兩把鑰匙，單位公尺）。

**怎麼用**
1. 在設定裡把「B 距 A」調成你實際量得的距離（例如 4.0 m），在現場選兩個點 A、B，兩點連線就是基地座標的 +x 軸。
2. 站在 A 點按「對位：站A點按我」，走到 B 點再按一次。
3. 完成後：
   - 基地模型（琥珀色牆、橘色假門、青色鑰匙）畫回鏡頭畫面。
   - 左下角小地圖顯示你在基地裡的位置與朝向。
   - 文字顯示基地座標、朝向、正前方牆距（對基地模型做射線）、最近鑰匙距離。
   - 被模型牆（隔間）擋住的鑰匙與假門不畫，也標示「被牆擋住」。
4. 「以對位修正步長」：用 A、B 實際距離與步伐推算距離的比值，修正步長（尺度誤差），之後請重新對位。

**數學**：`φ = angle(B_site − A_site) − angle(B_ar − A_ar)`，`p_site = R(φ)·(p_ar − A_ar) + A_site`。已用腳本驗證往返轉換誤差為 0、旋轉與尺度比正確。

**這版的限制**
- 沒有標記對位：iOS Safari 沒有可靠的條碼／標記偵測介面，要加就得引入額外的函式庫，先不做。
- 對位只修正一次起點與旋轉；位置仍靠步伐推算，走遠會漂移，需在已知點重新對位。Unity + ARKit 才有穩定的空間追蹤。
- 同時新增：偵測到的真實牆（世界模型）會遮擋它後面的虛擬建築。仍屬單眼估計，牆偵測有誤時會誤遮擋。

## v4：物體辨識（手機端，不需要金鑰）

設定面板 →「物體辨識」。第一次按會從網路載入 TensorFlow.js 與 COCO-SSD 模型（約 5–10 MB，需要網路，載入失敗會在資訊文字顯示原因）。

- **辨認什麼**：椅子、沙發、床、桌子、電視、筆電、鍵盤、書、瓶子、杯子、盆栽、冰箱、微波爐、行李箱、長椅等約 24 類。COCO 沒有「門」與「牆」，牆、柱、轉角仍由原本的幾何偵測負責。
- **定位**：物體框的底邊落在地面，用眼高與俯仰角算距離，換成 AR 座標，存進「物件記憶」，在畫面以黃綠色立體框顯示。距離小於 0.6 m 或大於 9 m 的不記錄。
- **點選卡片**：點畫面上的辨識框，顯示材質、用途、可能性、遊戲用途。**這些內容來自內建知識庫（對常見情況的描述），不是看影像判斷的**；要依影像判斷材質與狀態，需要之後的深度層（雲端視覺語言模型，需要金鑰與代理）。
- **接到生成**：椅、桌、沙發、冰箱、盆栽等「掩體」類，累積足夠次數後，會成為掩體群的錨點，虛擬掩體長在真實物體旁。
- **隱私**：偵測到「人」時完全不處理、不記錄。影像不離開手機。
- 驗證：用假偵測結果驗證距離換算（誤差 0）、人與過遠物體被忽略、辨識失敗不當機、點選與生成流程；**尚未用真實模型在真實手機上驗證**，辨識準確度與速度要實測。

## v5：Canny 邊緣偵測

在偵測格（每 4 像素一格）上跑完整的 Canny：高斯模糊 5×5 → Sobel 梯度 → 非極大值抑制（邊緣細成 1 像素）→ 雙閾值 → 遲滯（弱邊緣要連到強邊緣才保留）。閾值跟著設定裡的「點雲敏感度」：強邊緣門檻＝敏感度×0.9（至少 8），弱邊緣門檻＝強邊緣門檻×0.4。

用在三個地方：
- 垂直線偵測：Canny 邊緣決定「線在哪個方位」，Sobel 強邊緣只用來補完線的長度（角落處 Canny 常中斷，純 Canny 時垂直線底端會提早消失、距離會偏）
- 轉角的地牆交線追蹤
- 視野外圍的白色點雲：只留在 Canny 邊緣上，沒有邊緣的區域點變稀疏（偵測暫停時，例如手機快速轉動，會自動退回原本的畫法）

設定面板的「Canny 邊緣」開關可以和原本的 Sobel 做法比較；「顯示邊緣」開關疊圖：黃色＝強邊緣、洋紅＝連到強邊緣的弱邊緣（需要先打開「偵測層」）。

在合成房間裡，Canny 與 Sobel 兩種模式偵測到的牆、柱、轉角相同（柱距誤差約 4%）。真實場景的雜訊、反光、紋理比合成影像多得多，閾值可能要再調，請用「點雲敏感度」滑桿在現場調整。

## v6：多人連線（自架 WebSocket）

### 架構
```
手機 A ──wss──┐                       ┌── 指揮端網頁（電腦）：地圖、軌跡、共享狀態
手機 B ──wss──┼── server/server.js ──┤
手機 C ──wss──┘   (Node.js + ws)      └── /play/ ：同一個伺服器也能提供手機網頁
```
- 同一個「房間代碼」的人互相看得到；手機約每 100 ms 送一次位姿，伺服器每 100 ms 發一次快照
- **共享座標系**：雙點對位完成後（A 點、B 點，A=(0,0)、B=(L,0)），送出的是基地 site 座標，所有人共用同一套。沒對位的人送 AR 座標（各人自己的），只出現在清單，不畫在地圖，也不會顯示成別人眼中的人形。所以**每位玩家都要在同樣的 A、B 兩點各按一次對位**
- 對位完成後，別人會以「線條人形」出現在你的 AR 畫面（顏色＝玩家色，頭上有名字和距離）、羅盤雷達上；同樣受視野規則限制，被模型牆擋住就不畫
- 共享狀態（state）：任一人設定，所有人收到，後來加入的人也會先收到；適合放謎題旗標（門是否打開、誰拿了哪把鑰匙）。事件（event）只轉發一次、不保存。對位完成時，第一個對位的人會把基地模型（牆、物件）存進 `state.site`，指揮端用它畫地圖
- 懸疑事件會廣播：A 遇到邊緣人影，B 會看到「A 遇到了：邊緣人影」

### 在你的電腦上啟動
1. 安裝 Node.js 18 以上
2. 在 repository 的 `server` 資料夾裡：`npm install`，然後 `npm start`（預設埠 8080；可用 `PORT=3000` 改埠；`TOKEN=暗號` 設了就要求大家填暗號）
3. 瀏覽 `http://localhost:8080/` 開指揮端，填房間代碼後按「連線」

### 讓 iPhone 連得到：一定要 https／wss
手機打開的是 https 網頁（相機與感測器的限制），瀏覽器只允許它連 `wss://`，不能連 `ws://192.168.x.x`。最簡單的做法是用 https 隧道把你電腦上的伺服器接到網際網路：
- 例如 Cloudflare 的 `cloudflared tunnel --url http://localhost:8080`，會給你一個 `https://隨機名稱.trycloudflare.com`；ngrok 的 `ngrok http 8080` 也類似（兩者都要先安裝，細節與限制以官方文件為準）
- 之後有兩種開法：
  1. **一條連結搞定**：手機直接開 `https://隨機名稱.trycloudflare.com/play/`（伺服器順便提供手機網頁，伺服器網址已自動填好）。這需要 `server` 資料夾放在這個 App 的 repository 裡（`index.html`、`app.js` 在它的上一層）
  2. **網頁仍放 GitHub Pages**：手機開 `https://你的帳號.github.io/ar-vision/?server=wss://隨機名稱.trycloudflare.com&room=room1&name=小明`，按「開始」後會自動連線。也可以在「設定」面板手動填
- 要長期使用（不想開著電腦），可以把 `server` 資料夾部署到任何能跑 Node.js 並提供 https 的雲端主機（它們都會給你 `wss://` 網址）；價格與免費額度請看各平台目前的方案
- 沒有暗號的伺服器，任何知道網址和房間代碼的人都能進來；公開網址請設 `TOKEN`

### 安全與限制
- 伺服器有基本防護：單筆訊息 8 KB 上限、位姿頻率上限、房間代碼只允許英數與 - _、每房最多 16 人、共享狀態最多 64 個鍵；這不是完整的資安設計，請不要放敏感資料，也不要把沒設暗號的伺服器長期暴露在網路上
- 伺服器沒有存檔：重啟後房間狀態就清空
- 即時位置分享涉及隱私，請只在同意的人之間使用，並把房間代碼視為私密
- 位置是步伐推算（會漂移），兩位玩家的 site 座標誤差會累積，距離只適合當粗略參考；之後換成 ARKit 或標記對位會好很多
- 在測試環境裡驗證過：伺服器通訊協定（加入、位姿、狀態、事件、暗號、超大訊息、房滿、離線清理）和兩支模擬手機加指揮端的位置、距離一致；斷線後約 1 秒自動重連。尚未在真實手機與真實網路（隧道延遲、手機切到背景會被系統暫停連線）下測試

### 訊息格式（要自己加遊戲邏輯時）
| 方向 | 訊息 | 說明 |
| --- | --- | --- |
| 手機→伺服器 | `{t:'join', room, name, role:'player'\|'viewer', token}` | 加入房間（只能一次） |
| 手機→伺服器 | `{t:'pose', frame:'site'\|'ar', x, z, h, steps}` | 位置（公尺）、朝向（度，0＝-z） |
| 手機→伺服器 | `{t:'state', key, val}` | 設定共享狀態（`val:null` 刪除） |
| 手機→伺服器 | `{t:'event', kind, data}` | 一次性事件 |
| 手機→伺服器 | `{t:'reset'}` | 清空共享狀態 |
| 伺服器→手機 | `welcome`、`snap`、`state`、`event`、`join`、`leave`、`reset`、`error`、`pong` | 見 `server/server.js` |

網頁裡可呼叫 `__ar.netSetState('door1', {open:true})`、`__ar.netEvent('key', {n:1})`，收到的事件在 `__ar.net.events`，共享狀態在 `__ar.net.state`。

## v7：後台偵測、標記物定位、人物／敵人、速度視野

### 偵測與測量線移到後台
Canny 邊緣、牆線、角點、測距線預設不畫出來，畫面只留點雲、方位與遊戲元素。要看除錯畫面：網址後加 `?debug=1`。

### 標記物（A-1、A-2…）
- 在掃描到的牆面／柱面上自動生成。位置用 Canny 邊緣圖做距離變換，挑「離任何邊緣最遠、最平整」的一塊；標記物沿牆面法線貼齊（偏差修正會沿法線方向微調），柱子則貼在面對你的那一面。這是 ARKit 平面擬合的單眼替代版，iPhone 15 沒有 LiDAR。
- 編號由伺服器發：4.5 m 內沿用同一字母（A-1、A-2…），離遠開新字母（B-1…）。
- 啟用條件：距離 ≤ 1.5 m、面向標記物、標記物在中央清晰區內，並停留 0.7 秒。啟用後伺服器廣播，指揮端地圖上該點亮起。
- 標記物是「虛擬的」：它附著在偵測到的牆上，不是貼在現實的實體圖案。換一個人要先用 A／B 雙點對位，座標才會共用。

### 人物＝其他玩家＝敵人
- COCO-SSD 同時偵測 person 與 cell phone。手機框落在人框內，或位置和伺服器回報的某位玩家吻合（1.6 m 內），就是敵人，以白色框標記（四角加粗）。
- 被建築擋住不顯示：虛擬生成的建築、偵測到的牆、基地牆、大型物體都算。被矮物擋住時，只框露出的上半部。
- 伺服器上的玩家就算鏡頭沒拍到，也依座標判斷；被擋住一樣不顯示。

### 點雲密度與中央視野
- 周邊點雲密度＝中央區掃過該方向的次數：0 次 20%，5 次以上 100%。
- 中央視野大小隨你的移動速度變：不動最大（×1.15），快走縮到約 ×0.5。

### 伺服器（Windows）
```
cd server
npm install
npm start
```
- `/` 是指揮端地圖（玩家座標、標記物、牆），`/play/` 是手機 App。最多 3 人（`MAX_PLAYERS`）。
- iPhone 要 https／wss：用 `cloudflared tunnel --url http://localhost:8080` 或 ngrok，或部署到雲端主機。

## 已知限制

- 這是單眼啟發式偵測，不是 LiDAR，也不是真正的語義分割模型。距離來自「眼高 1.5 m + 俯仰角」，俯仰角誤差 2° 在 5–6 m 處約造成 20% 的距離誤差；握持高度不是 1.5 m 時請調整程式裡的 `EYE`。
- 垂直線底端若被家具、人或畫面下緣擋住就無法測距；強烈地磚花紋、玻璃反光、逆光會產生誤判，因此實體要累積多次才算數。
- 位置靠步伐推算，沒有真正的空間定位，走久了世界模型與你的位置會漂移；按「校準前方」會清空世界模型重建。
- 虛擬建築仍不會被真實物體遮住，也不會擋住你，請注意真實環境的安全。
- 以上流程在合成房間影像（已知牆、柱、轉角座標）和無頭瀏覽器中測過：轉角位置誤差約 1%，柱距離誤差約 4%；尚未在真實手機與真實場景驗證。

- v7 補充：單眼測距有誤差（遠處約 ±15%）；COCO-SSD 在逆光、8 m 以上、半身入鏡時會漏偵測；標記物是虛擬生成；各人座標系要先 A／B 對位；整套尚未在實機上測試，上線後請先用 `?debug=1` 檢查。
